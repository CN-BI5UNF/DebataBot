# D01 稳定账本基础（隔离实现，未生产迁移）

`core/d01.py` 在显式传入的 `debata.db` 上做 v1 -> v2 增量迁移，migration id
`M001`。默认拒绝看起来像生产实例的路径；测试只使用 tmp AppPaths。

## 新增契约

- `history_records` 增量列：`record_uuid`、persona 内单调 `record_seq`、
  `life_epoch`、`turn_id`/`raw_seq`、`visibility`/`deleted_at`。
- `corpus_state`：`next_seq`、`append_revision`、`mutation_gen`、
  `current_summary_gen`、`lifecycle_epoch`。
- `origin_messages` / `record_origins` / `record_copies`：来源与副本映射，
  同正文不等于同消息，多对多。
- `summary_generations` / `summary_sources`。
- `projection_outbox`、`delete_ops`、`tombstones`、`turn_checkpoints`、
  `action_ledger`、`legacy_import_ledger`。

## 迁移规则

- 保留旧 `record_json` 字节，不按 ID 回填重写；只为已有行分配 UUID/seq。
- 同正文的不同行不合并；`record_uuid`/`(persona,seq)` 唯一。
- 坏 JSON 行不跳过，计数写入 import ledger detail；映射不以“猜邻居”方式
  修复。
- import ledger 区分 `imported`/`valid_empty`；空表不自动重导旧文件。
- 重复迁移幂等；schema 高于 v2 拒绝。
- `append_record` 在同一短事务写 history + corpus_state + outbox；
  `tombstone_record` 同事务写 visibility/tombstone/delete_ops/outbox 并递增
  mutation_gen。删除不回收 seq。
- WAL/FK/busy timeout 保留；网络/大文件不在事务内。

## 语义证据与恢复重放

- `ledger_evidence(db, label=...)` 只读返回 schema/`M001`/per-persona 水位、
  history/tombstone/outbox 计数和 tombstone 指纹；不含正文、摘要或密钥。
  `aware` 表示 D01 结构存在，`complete` 还要求迁移后不变量成立（身份/SQLite
  序号非空、无重复 seq、`next_seq > max_seq` 等）。
- `aggregate_ledger_evidence` 聚合同一快照内全部 persona DB；path label 参与
  digest，重复 persona 或缺失探针会使 `complete=false`。
- `plan_restore_replay(snapshot_db, source_db)` 比较快照与当前源：
  `exact`、`replay_tombstones` 或 `blocked`。新消息、墓碑回退、epoch/ledger
  分叉均 blocked，不能裸覆盖恢复。
- `apply_tombstone_replay` 只对 `replay_tombstones` 生效：在同一事务中应用
  新增 tombstone/delete_ops/outbox，更新 visibility 和 `mutation_gen`，不改写
  raw `record_json`；相关 summary 标为 stale，`current_summary_gen=0` 要求
  重建。重放后在事务内复验墓碑集合和水位，失败回滚。
- `D01_CONTRACT_EPOCH = 1`。生产 M001 完成后，可信迁移工具必须把
  `compatibility_state.json` 推进到 epoch 1 / `M001`，并由维护屏障以相同值
  生成后续严格快照；普通 Runtime 不会自动写这个状态。

## 边界

- 没有在生产实例执行迁移；`DEBATA_DB_SCHEMA_VERSION` 仍是 v1，普通 Runtime
  不会自动打开 v2。
- 生产迁移仍需 U01-L 部署、M00 真实 writer 冻结、bootstrap permit、
  strict restore drill 和用户授权；缺失 ledger 的恢复必须 blocked。
- 恢复重放目前是 core API，只接入了测试；尚未接入 restore CLI 或在线一键
  恢复，也没有在生产数据上执行。
- 坏 JSON 的具体内容不打印，只在 ledger 记录计数/指纹。
