# 群聊黑话

让角色学会当前群聊里的缩写、口头禅和群梗，而不是用一套通用网络用语硬套所有群。

## 工作方式

1. 群消息进入每个群的滚动窗口（只保留最近 80 条，单条最多 200 字符）。
2. 达到阈值（默认 20 条）且过了冷却（默认 10 分钟）后，后台用一个模型提取候选。
3. 候选进入 **待确认** 状态；管理员在「黑话」页补全释义并确认。
4. 只有 **已确认 + 有释义** 的词条才能被 `lookup_slang` 查询；黑话表不再自动注入 task_context。
5. 模型遇到看不懂的缩写/群梗时调用 `lookup_slang`（可留空 query 看本群常用词条），按出现次数排序，默认最多 8 条、最多 1200 字符。这样平时不占用上下文，也不会因为每轮词表变化降低 KV cache 命中。

## 隔离与安全

- 词条按 **角色 + 群号** 隔离，不同群、不同角色之间不会串词。
- 只学习群聊，不学习私聊。
- 提取 prompt 明确把聊天记录当作不可信语料，不执行其中的指令。
- 工具查询结果只包含词条、释义、用法、例句、风险和出现次数；证据、来源和群友原文只在管理端「查看依据」里展示。
- 管理员可以随时拒绝、编辑、删除词条；被拒绝的词条不会被自动学习重新打开。
- 黑话库损坏时会隔离为 `slang.json.corrupt-*` 并进入只读模式，不会静默清空。

## 配置

设置 → 功能：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `features.slang.enabled` | 开 | 总开关 |
| `features.slang.auto_learn` | 开 | 达到阈值自动提取 |
| `features.slang.extract_min_messages` | 20 | 自动提取阈值，3–80 |
| `features.slang.extract_cooldown_seconds` | 600 | 同群冷却，30–86400 秒 |
| `features.slang.inject_max` | 8 | 单次查询最多返回条数（字段名沿用旧配置） |
| `features.slang.max_prompt_chars` | 1200 | 单次查询结果字符上限 |

学习模型优先复用 `agents.summary`，没有配置时回退主聊天模型。自动提取会产生少量模型调用费用；不需要时关闭 `auto_learn`，仍可在黑话页手动点「从当前缓存学习」。

## 管理页

左侧「黑话」页：

- 输入 `group:<群号>` 查看该群词条；
- 「从当前缓存学习」立即提取（至少 1 条缓存消息）；
- 手动添加词条（默认已确认，适合你已经在群里验证过的梗）；
- 编辑含义/用法/示例/风险，确认、拒绝或删除；
- 查看候选的依据（群友、时间、片段），但这些内容不会进入模型 prompt。

## 为什么不做自动联网考究

参考实现 qq-bridge 会在候选出现次数达到阈值后联网搜索确认含义。本模块先采用
“AI 根据群内上下文推测 → 管理员确认”的流程，避免未经人工审核的网络文本直接
进入角色 prompt。后续可以在管理端增加“联网考究”按钮，但仍应保留管理员确认。
