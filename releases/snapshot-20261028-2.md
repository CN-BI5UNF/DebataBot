# 开发快照 2026-10-28-2

本快照修复 `2026-10-28-1` 的升级阻断问题，并撤回该版本。

## 修复：升级后无法进入 WebUI

旧配置里的 `persona.active: debata` 在 `debata` 内置人格被移除后会让 Runtime 启动失败，WebUI 显示：

> 读取配置失败：未找到人格 'debata'。可用人格: ['deepseek', '大肥鱼']

配置保存在实例数据目录（如 `~/.local/share/Debata_Agent/instances/default/config.yaml`），所以删除项目重新拉取也无法解决。现在：

- Runtime 启动时会自动解析人格：已移除的 `debata` 优先映射到 `deepseek`；
- 若 `deepseek` 也不可用，回退到默认人格「大肥鱼」，再否则选择第一个可用人格；
- 修正结果会写回 `config.yaml`，并在 `config_backups/` 生成一份带时间戳的备份；
- 配置只读或写回失败时，本次运行仍使用兜底人格继续启动，只在日志中告警；
- 用户自己保留/重建的 `personas/debata/` 目录仍优先加载，不会被强制改名；
- 没有任何可用人格时仍会给出明确错误，不会静默启动。

CLI 配置向导的默认人格已从 `debata` 改为「大肥鱼」；向导里“Debata 等仓库自带人格”等过时文案更新为「大肥鱼 / deepseek」。

## 数据说明

自动切换不会删除旧数据。`debata` 的记忆数据库仍保留在 `memory/debata/`；新激活的 `deepseek` 人格使用自己的 `memory/deepseek/` 目录，因此旧会话不会自动出现在新人格下。需要保留旧会话时，请先备份 `memory/debata/`，再按需迁移。
