# 开发快照 2026-10-30

本次快照包含 GIF/视频完整输入、QQ 原生表情适配、受控 Docker 容器、启动依赖自检、中转站模型厂商适配，以及模型管理与侧栏交互调整。

## 聊天与媒体

- **完整 GIF 输入**：不再只取首帧，保留原始 GIF 字节并作为 `image/gif` 发送；仍支持首帧兼容模式。
- **完整视频输入**：保存并发送完整视频文件，不转码、不抽帧；仅对已核实的能力和协议开启，不支持时保留 workspace 占位。
- **待注入媒体修复**：工具循环期间新到达的消息会在模型副本中正确投影图片/视频，避免 `image_projection_failed` / 图片块与资产引用不一致。
- **QQ 原生表情**：内置 275 个 NapCat 表情 ID 映射；`[CQ:face,id=5]` 显示为 `[流眼泪]`，发送工具支持按 `face="流眼泪"` 或表情 ID 发送。
- 媒体预算、请求体护栏、视频 token 预留和 provider 图片/视频校验同步更新。

## 受控 Docker 容器

- 新增 `container` 工具：执行命令、读写 `/workspace`、导入导出、状态、存储诊断和重建。
- 默认使用 **B 命名卷**，免管理员、开箱即用；**C 固定大小镜像**作为高级硬上限。
- C 首次启用支持 Linux sudo 密码弹窗（仅 stdin，不保存、不写日志）和 Windows UAC 确认。
- 启动时后台检查 Docker/镜像，缺失时自动拉取；新增 Docker 镜像加速前缀，拉取后 tag 回原镜像名。
- 容器页改为「一键准备 / 启动」，集中显示 Docker、镜像、存储和容器问题，并提供修复按钮。
- 修复 C 存储实际大小与配置不一致导致反复初始化失败的问题；新增“采用实际大小”操作和安装脚本前置校验。
- 复用已存在的镜像源 tag，避免网络中断后重复下载；镜像检查/拉取/标记串行化。
- 安全默认保持 cap-drop ALL、no-new-privileges、只读根文件系统、非 root、无网络（需显式开启）、只挂载专用 workspace。

## 依赖与启动

- 正常启动在导入应用前检查 `pyproject.toml` 的基础依赖；缺失或版本不符时自动用 uv/pip 执行 editable 安装。
- 只安装基础依赖，不自动安装 optional/dev/本地模型重依赖。
- 支持 `KAREN_DISABLE_DEPENDENCY_CHECK=1` 和 `KAREN_DISABLE_DEPENDENCY_INSTALL=1`。
- 启动日志会明确记录依赖检查结果。

- 侧栏新增折叠按钮，折叠后只显示图标，状态保存在浏览器本地。
